# Volatility 缺失插件实施计划

目标：补齐固定 Volatility 3 v2.28.2 的 Linux / Windows 插件、参数和输出能力。
完整验收仍遵循 [对齐进度](volatility-parity.md)，不能以入口存在代替功能完成。

## 共享基础先行

现有基础：只读镜像和虚拟地址空间、精确符号、可取消有界遍历、任务链恢复、
部分结果诊断、CLI/TUI/MCP 共用插件描述，以及固定参考版本的逐字段差分工具。
新增插件必须复用这些基础；缺页不填造值，残缺视图不能证明对象不存在。
原 CLI 入口和已有字段保持兼容；新增官方完整入口单独注册。

实施次序：

1. 人工复核 inventory 的候选映射，区分真正缺失与命名不同；保留参数和字段缺口。
2. 补进程身份比较（ProcessSpoofing），复用文件路径与用户内存读取；覆盖名称截断、
   已删除文件、空参数、缺页和取消，并对真实样本逐字段比较。
3. 补模块跨视图、模块提取与 kallsyms，抽取共享模块枚举/符号读取基础。
4. 补物理任务与套接字扫描，抽取结构候选验证、去重与扫描覆盖证据；不能把链表枚举
   当作扫描实现。
5. 补 VMA 正则、调用栈和 framebuffer；明确模式语义、架构与文件输出约束。
6. 补 Windows GUI、系统调用检测、注册表/内存扫描等未覆盖项，并完善已有插件的
   官方参数和完整字段。各平台按依赖推进，不以整个系统单次大改为前提。

每批更新实现与证据，执行相关回归、make check；重大变化 commit + push。
不自动发布 release。参考 Python 仅用于开发测试，不能成为 Zero 运行时依赖。

## 验收记录

每个插件记录：参考源码哈希、入口、参数、全部输出字段、异常语义、正向真实样本、
差分结果和剩余限制。只有这些条件有证据时才提升为 verified。
合成测试证明边界处理；空输出或仅共有字段一致不证明完整对齐。

初始状态：135 个正式插件均未通过完整插件验收；现有 5 项 PsList 全字段差分通过。
后续的能力增长与完整验收数量分别报告。

首批实现：ProcessSpoofing 已接入原生引擎和公共插件描述，新增身份源比较及边界测试；
默认与单 PID 的公开样本差分通过，保留两处真实缺页诊断。下一批推进共享模块视图与
Modxview；多 PID 列表仍作为公共参数基础缺口保留，不因本批单 PID 通过而关闭。

第二批实现：共享 module_kset/list/carving 与分配范围基础已抽取到 modules.rs；
Modxview 实现三个独立视图和 taint 两种输出，默认及 plain-taints 的公开 Debian 样本
差分通过。真实隐藏/tainted 模块和现代内核的边界差分仍需补齐。接下来推进共享模块
ELF/section 读取基础及 ModuleExtract，不跳过前述未验收边界。

第三批实现：共享模块符号/section 读取及原子重建文件发布基础已落地；ModuleExtract
的 x86_64 入口接入 CLI/TUI/MCP。两个公开 Debian 模块的全字段与 ELF 文件内容比较通过，
缺页补零范围显式保留。32 位重建、现代内核真实样本及边界差分仍在缺口中；下一步继续
kallsyms 共用的模块符号读取与核心符号解码，不把本批能力视为完整插件验收。

第四批实现：Kallsyms 的四个来源和来源参数已落地；复用模块符号基础，并加入压缩名称、
地址模式确认、别名尺寸、markers 恢复与来源隔离。Debian 四项全字段差分通过，Kali ARM64
核心枚举另有实际验证。动态 ftrace/BPF、现代配置真实差分及 32 位仍未完成验收。
后续继续补物理任务/套接字扫描的结构验证与覆盖证据，同时保留前述未验收边界。

物理扫描批：先新增共享 `physical` 模块，支持 4/8 字节指针、分块与连续区段边界、
空洞隔离、覆盖统计、取消、命中/输出上限及调用方停止；再实现 `linux.psscan.PsScan`，
物理读取候选字段，父对象通过内核虚拟层读取。合成用例覆盖未链接任务、线程 TGID/TID、
四种退出状态、父对象不可读及连续 LiME 区段。真实默认参数差分和验收记录见对齐进度。
下一批继续复用该基础实现独立 Sockscan 的 file-ops 与 destructor 两个来源，不能以现有
基于文件描述符的 sockstat/netscan 代替物理扫描。其余 Linux/Windows 缺口保持原范围。

套接字批：先实现区分物理嵌入字段与虚拟指针目标的公共套接字字段读取，再接入
`linux.sockscan.Sockscan` 的 file-ops / destructor 两个扫描来源。覆盖八个家族及
socket/reuseport 过滤器，按解析后的物理地址去重。默认参考比较保留重复行和 IPv6 读取层
差异，不改变原始产物来制造一致。验收工具新增显式记录排除数量的局部行选择，仅证明
声明范围内的全字段；只有局部行证据不能完成整个插件的验收。
后续推进共享 VMA 正则基础与 VmaRegExScan，再继续调用栈、framebuffer 与 Windows 缺口。
此前各批的架构、内核、损坏样本及完整参数验收缺口继续保留。

VMA 正则批：先实现有资源上限的原生 PCRE2 字节封装与共享驻留虚拟区域扫描器，覆盖
相邻 VMA、物理不连续页面、缺页隔离、分块重叠、短尾、上下文补零统计和前缀结果保留。
再实现 VmaRegExScan、扫描前多 PID 筛选及 maxsize，并接入 CLI/TUI/MCP 和缓存身份。
默认参数、前后查找、反向引用、多 PID 和全进程样本分别比较全部字段；参考未应用 maxsize
的差异独立保留。下一步继续调用栈共享读取基础和 PsCallStack，再补 framebuffer 与 Windows
缺口。Python re 的完整语法矩阵、32 位、更多内核和损坏样本仍属于完整验收范围。

PsCallStack 批：先抽取共享主任务/线程枚举、带来源与别名优先级的不可变运行时区间索引、
可取消的栈字读取基础，再接入 PsCallStack。PID 筛选在主任务阶段执行，输出保持线程 TID；
索引按 core/module/BPF/ftrace 优先级查询，模块符号使用捕获 ELF 的有效长度。SP、缺页、
内核映射回退与固定 16 KiB 窗口均记录。参考模块查询的未解析差异独立保留，边界运算优先级
问题已在源码中发现，但未单独证明全部差异的因果；
完整默认比较继续失败；完整可比较任务与明确选择的核心行范围分别验收。
下一步补 framebuffer 的共享图像/定向文件输出基础与 Fbdev，再继续 Windows 30 个入口、
既有插件参数/架构/损坏样本验收。增加入口和局部差分不关闭完整目标。

Framebuffer 公共基础先行：新增 `src/framebuffer.rs`，通过已验证的 packed-pixel 布局按行
读取，尊重 stride，支持 RGBA 位域、位序翻转、无 alpha 的不透明输出。使用现有原生 zlib
依赖流式写入标准 RGBA PNG，每个 IDAT 不超过 64 KiB；源缓冲 256 MiB、像素 16 Mi 上限，
布局和地址溢出在 I/O 前校验，读取与转换可取消。原子发布复用 store，缺页或取消不能覆盖
已有文件。测试覆盖 RGB565、padding、RGBA、多 IDAT、缺页、取消和错误位域。颜色值按固定
参考保留未缩放整数（超过 255 饱和），不会把低位深通道隐式放大。该基础不算 Fbdev 已实现；
下一步接入 fb_info 枚举、默认八字段、定向 PNG/RAW 导出及各入口和实际样本差分。

Fbdev 批：在已提交 PNG 基础上新增 fb_info 注册枚举和可选导出；共享流式文件发布计算摘要、
限制字节数并保留既有文件。统一区分“必须转储”和“支持可选转储”的插件，Fbdev 默认列举，
CLI/MCP/TUI 显式导出，Session 可选导出不能读写分析缓存。八字段、选择器、PNG/RAW、设备名
不可读、空槽、缺页、不覆盖及缓存隔离分别验证。实际 Debian 为空；Kali 有真实 PNG 输出，
固定参考只支持 Intel 层，不能计入 ARM64 全字段差分。生成数据的转换函数差分单独记录，
不替代真实样本验收。Linux 已无缺失入口，下一批继续 Windows 30 个缺失入口，优先复用
VMA 正则/窗口对象和扫描基础，随后推进全量参数、架构、异常与真实样本矩阵。

Windows VAD 正则批：先共享上下文补零统计、非 DOTALL 锚定重匹配和 Text/Hex 格式化，复用
现有 PCRE2 与驻留范围扫描器，再接入 VadRegExScan。VAD 枚举保留损坏树前缀，扫描所有
保护属性、合并相邻范围、使用 Windows 页面恢复层，PID/列表在枚举前取并集。CLI/MCP/TUI
同步参数和缓存身份，Windows 结果不能在并集扫描后再次按单 PID 截掉列表结果。默认全部
五字段与多 PID、前后查找、反向引用分别验收，maxsize 参考未应用的差异单独保存；版本
兼容矩阵只登记实际取得的证据，入口增加不等于全平台完成验收。

真实 Windows 正则样本补充了两项公共基础：共享扫描器接受经页表验证的稀疏空区间提示，
所有跳过字节仍计入未读覆盖；Windows 只对零页表项提供提示，非零软件 PTE 和缺失表页仍
走正常恢复路径。另抽取 VAD 树布局，扫描使用最小 tag/范围遍历，不因无关文件名或保护
字段不可读而丢弃范围；父链异常保留诊断并继续验证带 tag 的子节点。命中起始页若经恢复，
记录 prototype 或 software/compressed 来源。真实 prototype 扩展差异与 maxsize 参考差异
分别保存，不删除恢复命中来制造默认一致。后续继续 Windows 剩余入口和完整矩阵验收。
